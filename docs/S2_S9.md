# S2 (scCP apo) and S9 (scCP + pac RNA): step by step

Needs one file you make: the single-chain CP model. Everything else is the same
pipeline as S1/S6/S4. Commands go in MSYS2 UCRT64 on a lab PC (use `python`, not
`python3`), one at a time.

## 1. The model (you)
- ONE protein chain: CP copy 1 - linker - CP copy 2, continuous numbering.
- The two CP copies must sit like the native C/C dimer (S1).
- Make it with AlphaFold3 / ColabFold from the full scCP sequence, or graft the
  linker on the 2MS2 dimer.
- No hydrogens, waters or ligands.
- Superpose it on S1 (`input/S1_wt_cc_apo/S1_wt_cc_apo.pdb`) and write down the
  backbone RMSD BEFORE simulating (the control for "the linker does not distort the fold").

Put the SAME file in both places:

    input/S2_sccp_apo/model.pdb
    input/S9_sccp_pac/model.pdb

## 2. Build the PDBs
    cd ~/BruSafe-MD-simulations && git pull --no-rebase
    python scripts/00_build_inputs.py build S2_sccp_apo
    python scripts/00_build_inputs.py build S9_sccp_pac

- S2 writes `input/S2_sccp_apo/S2_sccp_apo.pdb`.
- S9 aligns the model to the two CP chains of S4 (the linker drops out as an
  insertion), superposes on CA, refits on the rigid core, and takes S4's RNA and
  Mg. It prints the core RMSD (above 2 A it only WARNS: fix the model), the
  linker residues, and any protein-RNA pair closer than 2 A (a linker or loop
  running through the RNA: rebuild that region).
- S9 needs `input/S4_cp_pacdesign/S4_cp_pacdesign.pdb` (already in the repo).

## 3. CHARMM-GUI (once per system)
charmm-gui.org -> Input Generator -> Solution Builder.
1. Upload `input/<system>/<system>.pdb`.
   S2: protein only. S9: protein + RNA + the 5 Mg (HETATM).
2. PDB manipulation: termini NTER/CTER on the protein; S9: confirm the nucleic
   acid is read as RNA, 5'-OH / 3'-OH. No mutations.
3. Water box / ions: anything (discarded; the scripts rebuild box, water, KCl, Mg).
4. Input generation: CHARMM36m, GROMACS, 310 K. Leave hydrogen mass repartitioning UNTICKED.
5. Download, extract, copy the `gromacs/` folder to `input/<system>/gromacs/`
   (it must hold step3_input.gro, topol.top, toppar/).
6. Commit and push:

       git add input && git commit -m "Add CHARMM-GUI builds for S2 and S9" && git push

## 4. Test the build on one PC (about 1 minute)
    ./scripts/01_prepare.sh S2_sccp_apo --source charmm-gui --replica 1 2>&1 | tail -15
    ./scripts/01_prepare.sh S9_sccp_pac --source charmm-gui --replica 1 2>&1 | tail -15

No FATAL; S9 must list RNA, RNA_BB, RNA_P and MG groups.

## 5. Plan and launch
Ask for the plan to be regenerated:

    python scripts/_registry.py plan --machines 8 --tier 2 --systems S2_sccp_apo,S9_sccp_pac --nsday 450 > /tmp/plan.txt

S2: 3 x 100 ns (about 5-6 h each). S9: 5 x 30 ns (about 1.5-2 h each).
One run_slot per PC, one slot number per PC:

    cd ~/BruSafe-MD-simulations && git pull --no-rebase && ./scripts/run_slot.sh N 16 > slot_N.log 2>&1

Progress, in a second terminal (refreshes every 30 s):

    cd ~/BruSafe-MD-simulations && ./scripts/progress.sh watch

## 6. After the runs
- `04_postprocess.sh` and packing run by themselves at the end of each slot.
- ddG S9 - S4: MM/PBSA (`mmpbsa/run_mmpbsa.sh`) on Linux/WSL/macOS, dropping frames
  where a Mg sits at the protein-RNA interface (`analysis/mg_interface.txt`).
- S2 vs S1: `analysis/compare_systems.sh S1_wt_cc_apo S2_sccp_apo` (subspace
  overlap above 0.7 supports "same essential dynamics").
